## 왜 이 문서가 먼저인가

힉스필드는 원세컨드에 처음 들어오는 외부 서비스다. "연동"의 구체 형태가 코드·문서·소식지 어디에도 정의돼 있지 않다. 이 상태에서 제품 코드(app.html 등)를 바로 짜면:

- **데이터 유기체 4대 질문**을 통과하지 못한다.
- **하드코딩 페이지 추가 금지** 원칙에 걸린다.
- 잘못 짠 화면을 되돌리는 비용이 문서 한 장보다 훨씬 크다.

그래서 **화면 전에 원장/기획**을 먼저 세운다. 이 문서로 범위를 확정하면 곧바로 구현(os-builder 위임)으로 넘어간다.

## 데이터 유기체 4대 질문 (착수 전 강제)

| # | 질문 | 현재 답(미정) |
|---|---|---|
| 1 | 이 화면이 **어떤 데이터 원장**을 조회하는가? | ❓ 힉스필드 연동의 산출물(생성 이미지/영상? 링크?)을 어디에 적재할지 미정 |
| 2 | 그 데이터는 **어디서 관리**되는가? | ❓ 힉스필드 측 API 응답 vs 원세컨드 DB 저장 여부 미정 |
| 3 | **다른 화면에서도 재사용** 가능한가? | ❓ 산출물이 자료실/카드/설계서 등에서 재사용될지 미정 |
| 4 | **권한 격리**는 지켜지는가? | ❓ 생성물이 개인(owner_id) 격리인지 공용인지 미정 |

→ **4개 모두 대표님 범위 확정 후에만 답이 채워진다.**

> 판단 기준: **"이게 임태성 실장 실제 영업에 바로 도움되는가?"**

- 힉스필드 = AI 이미지/영상 생성 서비스. 영업용 홍보 콘텐츠(카드·썸네일·소개 영상) 제작에 쓰일 수 있으면 **영업 무기 정합** ✅.
- 단순 외부 링크만 걸면 원세컨드가 "힉스필드로 나가는 통로"일 뿐 데이터 유기체에 붙지 않음 → 정합 약함.
- **권장:** 산출물이 원세컨드 안(자료실/카드)으로 되돌아와 재사용되는 방향이 전략에 가장 잘 맞음.

## [범위 선택] — 대표님 확정 필요 (택1)

### A. 메뉴/링크 카드 (가장 가볍고 되돌리기 쉬움 · A~B등급)
- 홈 또는 자료 허브에 "힉스필드" 진입 버튼/카드 추가 → 외부 힉스필드 사이트로 이동.
- API 연동·시크릿 없음. 구현 반나절 이내.
- 한계: 데이터 유기체에 안 붙는 단순 링크. 하드코딩 페이지 원칙과 소폭 상충(카드 1개 수준이라 경미).

### B. API 연동 — 생성 기능 (핵심 가치 · C등급 위험 포함)
- 힉스필드 API로 이미지/영상 생성을 원세컨드 화면 안에서 호출.
- 구조: 화면 → Edge Function(`higgsfield-generate`) → 힉스필드 API → 결과 저장(자료실/카드 원장) → 화면 재조립.
- **선행 필수:** 힉스필드 API 키 = 외부 시크릿(C등급). 대표님 계정 인증 1회 + GitHub Environment secret 등록(AI팀이 CI로 처리).
- 권한 격리: 생성물 owner_id 개인 격리 기본.

### C. 자료 채굴 소스 연동 (데이터 유기체 순환계 · 중간 난이도)
- 힉스필드를 소식지/자료실처럼 **채굴 원천**으로 붙여 콘텐츠를 DB에 적재.
- 검수 전 추출물 `ai_draft/hold` 분리 → `approved`만 화면 노출(채굴 격리 원칙 준수).
- 힉스필드가 "자료를 공급하는 소스"일 때만 의미 있음(생성 서비스 성격상 B가 더 자연스러울 수 있음).

**총괄 권장:** **B(API 연동 생성 기능)** — 영업 무기 정합이 가장 높고 데이터 유기체에 붙는다. 단 C등급(외부 시크릿)이라 대표님 API 키 인증 1회가 선행. 빠른 착수를 원하시면 **A로 1차 진입 후 B로 승격**하는 단계 전략도 가능.
