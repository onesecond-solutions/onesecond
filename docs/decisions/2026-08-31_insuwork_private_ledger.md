# 임태성 전용 간단 가계부

## 셀 편집 지출표
- 납입기한 B열은 숫자 키패드 입력을 지원한다. 연월일 8자리 `20260925` 입력/붙여넣기는 유효한 날짜일 때 즉시 `2026-09-25`로 정리한다. 부분 입력·잘못된 날짜는 원문을 유지하고 날짜 확인을 안내한다. 월말/윤년을 임의 보정하지 않는다. 기존 ISO 날짜 저장값은 변경하지 않는다.
- 대표 승인: 행 추가·삭제·복사, 간단한 수식·자동합계·사칙연산 방식으로 수정.
- A 항목 / B 납입기한 / C 예정 금액 / D 실제 납부액 / E 납부 완료 / F 메모. 모든 달의 행을 한 표에서 편집하고 ‘표 저장’으로 반영. 월별 요약만 납입기한으로 나눈다. Enter 다음 행, Tab 다음 칸.
- C/D열에 숫자, 사칙연산·괄호·셀 참조·SUM 범위 수식. 원 단위 반올림. eval/Function 실행 없음. 순환·0 나눗셈·삭제 셀·잘못된 수식은 오류를 표시하고 저장/합계 확정 금지.
- 합계용 행은 월별 지출과 표 하단 자동합계에서 제외해 이중 집계를 방지. 행 삭제 시 참조 이동, 직접 삭제 셀은 #REF!. 복사는 상대 참조 이동, 실제 납부액과 완료 상태 초기화. 행 번호 2부터, 최대 500행.
- 지출표는 같은 owner/private/settings 범위의 단일 메모(sheet payload)로 원자 저장. 임의 revision UUID를 비교하는 낙관적 잠금, 최초 저장은 고정 UUID로 중복 표 생성 방지. 기존 plan/entry 행은 변환·삭제하지 않고 하단 접기 영역에서 계속 관리하며 plan은 월별 요약에 합산.
- 편집 중 임시값임을 표시하며 실패 시 입력 유지. 페이지 이탈 시 브라우저 경고. 다른 기기 수정과 충돌하면 저장을 중단하고 재조회 안내. 운영 DB 검증 쓰기·DDL·RLS 변경 없음.
- 검증: 수식 6개·기존 가계부 8개·로딩 6개·모바일 라우팅 8개 통과. 모의 브라우저에서 행 추가/복사, C2 참조 사칙연산, SUM 합계행, 원자 저장·재조회·두 번째 저장, 납부액 변경 확인. 503 실패와 revision 충돌 시 내용 보존 확인. 390px 문서 폭 375px, 표 컨테이너 349px 안에서 1010px 표만 가로 스크롤.
- 배포: feat/insuwork-ledger-sheet → PR #1919 → 병합 8e84d681. Pages 33356788614 성공. 라이브 PC 지출표 헤더·A~F 열·변경 없는 저장 버튼 비활성·기존 두 관리 영역 확인. 모바일 /m/section.html에서 동일 화면, 문서 375px/뷰포트 390px 확인. 실물 기기 및 운영 DB 저장·수정·삭제 테스트는 미실시. 모의 행 삭제 후 SUM 범위와 자동합계 재계산도 확인.

## 예정 지출 중심 개편
- 대표 목적: 이번 달·다음 달의 고정지출과 예상 금액을 케어 일정처럼 미리 확인. 수입·지출 기록은 하단 접기 영역에 보존.
- 고정지출은 항목·매월 결제일·시작 월·예상 금액을 한 번 등록하면 조회 월별로 계산해 표시한다. 날짜별 거래를 DB에 미리 생성하지 않는다. 29~31일이 없는 달은 말일 적용.
- 일회성 예정 지출은 지정 날짜에만 표시한다. 이번 달/다음 달 요약, 선택 월 날짜별 예정 목록, 납부 완료/실제 금액/납부일/납부 취소 제공.
- 예상 총지출 = 이미 납부한 실제 금액 + 미납 예상 금액. 일반 수입·지출 기록과는 별도 집계하며 화면에 명시. 월별 납부 상태는 서로 독립적이다.
- 같은 비공개 메모 키 안에 plan payload를 추가한다. 기존 entry payload와 운영 데이터는 변환하거나 삭제하지 않는다. 예상 금액 수정은 선택 월 이후 버전으로 보존하며 반복 중단은 종료 월로 처리한다. 이미 납부한 달의 실제 금액은 보존한다.
- plan 변경은 읽은 legacy_payload와 일치할 때만 PATCH하는 낙관적 잠금으로 다른 기기의 변경을 조용히 덮어쓰지 않는다. DB/RLS/권한 변경 없음. 운영 저장 테스트 없음.
- 검증: 가계부 8개(기존 4개+반복/말일/윤년/납부 반영/변경 이력), 기존 로딩 6개와 라우팅 8개 검사 통과. 모의 저장소에서 매월 31일 20만 원 등록 → 이번 달 18만 원 납부 → 다음 달 22만 원으로 수정 → 다음 달 일회성 5만 원 추가를 확인. 이번 달 18만 원·남은 0원, 다음 달 27만 원·남은 27만 원으로 분리됨. 390px 문서 폭 375px.
- 개편 배포: PR #1918, 병합 9be5e80b, Pages 33353347801 성공. 라이브 PC에서 예정 지출 헤더·이번 달/다음 달 카드·등록 폼·기존 기록 영역과 조회 성공 확인. 휴대폰 UA/390px에서 /m/section.html의 동일 화면 및 가로 넘침 없음(문서 375px) 확인. 운영 쓰기는 하지 않았다.

- 대표 요청: “임태성 게이트에 너무 복잡하지 않은 가계부를 만들어줘, 나만 사용할거야.”
- 보험워크 전용, onesecond 저장소. 다른 제품은 수정하지 않는다.
- 지정 user_id 98c5f4f9-10c1-4ee1-a656-5c2ca63239fd와 로그인 세션이 있을 때만 PC/모바일 메뉴와 화면 허용. 직접 URL과 데이터 요청에서도 재확인한다. 관리자 전체/테스트 계정 예외 없음.
- 날짜·수입/지출·원 단위 금액·분류·내용 입력, 월별 수입/지출/차액, 내역 수정·삭제. 카드 연동·예산·차트 없음. 빈 상태로 시작한다.
- 기존 insuwork_items 비공개 memo를 재사용한다. 각 거래를 별도 행으로 저장하고 legacy_payload.workspace_category=settings, setting_key=personal_ledger_v1로 일반 자료·즐겨찾기에서 제외한다. 기존 owner_id RLS가 서버 데이터 경계이며 클라이언트 메뉴 게이트를 보안 경계로 간주하지 않는다.
- 신규 DDL·권한·RLS 변경 없음. 운영 DB에 검증용 거래를 쓰지 않는다. 테스트는 모의 저장소에서 실행하며 라이브는 조회와 화면만 검증한다.
- 사용자 저장은 private/owner_id 고정, 수정·삭제도 owner_id/setting_key/private/id 필터 적용. 삭제는 deleted_at 설정. 조회 실패를 0원으로 표시하지 않으며 실패한 입력은 보존한다. 신규 저장 재시도는 동일 UUID로 중복 생성 방지.
- 계정 저장 방식이므로 같은 계정의 PC·휴대폰에서 조회할 수 있다. 금융 데이터는 공개 JSON·저장소·로그에 넣지 않는다.
- 검증: 단위 검사 4개(게이트/조회 범위/날짜·금액/합계), 기존 모바일 라우팅 8개·로딩 6개 통과. 로컬 모의 저장소에서 12,000원 입력 → 15,000원 수정 → 재조회 → 삭제 확인. 503 저장 실패 시 내용·금액 보존 확인. 390px 가로 넘침 없음. 운영 DB 쓰기/실물 휴대폰 검증은 미실시.
- 라이브: PR #1917, 코드 병합 5d132b7c, Pages 실행 33352476487 성공. 실제 로그인 PC에서 가계부 메뉴·월별 0원·빈 내역(조회 성공)을 확인했다. 휴대폰 UA/390px에서 전용 /m/section.html?view=insuwork&section=ledger로 연결되고 상단 가계부 메뉴, 문서 폭 375px을 확인했다. 라이브 저장·수정·삭제는 운영 쓰기 제한에 따라 실행하지 않았다.
