# 보장분석 형식 구분·다중 원본 연결 — 2026-09-12

## 원인과 변경
- 카카오페이 표는 보장구분 머리글 아래에 상품·갱신 여부·보험료가 있다. 뱅크샐러드는 머리글 위에 보험사·보험료가 있다. 머리글 구성으로 구별하고 보장 시트를 찾아 읽는다.
- 브라우저 암호화 엑셀 라이브러리의 Buffer/process 초기화를 의존 모듈 실행 앞으로 옮긴다. 비밀번호는 입력 후 복호화에만 쓰고 저장하지 않는다.
- 표적 항암치료비 → 표적항암약물치료비, 중입자 항암치료비 → 항암중입자방사선치료비를 명시적 동의어로 연결한다. 기본 양식에 있는 빈 담보는 유지하되 원본에서 미가입인 미매칭 항목은 새 행으로 추가하지 않는다. 가입된 미매칭 담보는 원문을 보존한다. 고액암 진단을 자동 제거하지 않는다.
- 현대해상 실손의료비보장보험 Hi2307은 확인한 해당 상품 약관에 따라 4세대 실손으로 표시한다. 종합보험의 임의 숫자 코드를 세대 근거로 사용하지 않는다. 0원인 다른 상품 열이 세대 구분을 방해하지 않게 한다.
- 여러 파일을 선택하면 순차 분석한다. 선택 묶음에서는 엑셀을 먼저 연결하고 이미지/PDF로 빈 정보를 보완한다. 같은 회사·상품은 공백 및 무배당 접두어 차이를 정규화해 연결하고, 반복 자료의 가입금액은 합산하지 않는다.
- 서로 다른 양수 금액은 앞서 연결된 값을 유지하며 원본명과 다른 금액을 함께 보관한다. 상단에 금액 차이 안내, 담보명 툴팁에 상세 표시한다. 서로 다른 보장 조건이나 요약 금액은 개별 특약으로 임의 분배하지 않는다.
- 계약 정보만 있는 이미지를 허용한다. 보장·계약 항목 없는 보험료 개요는 금액 행으로 넣지 않고 원본 보관 및 안내한다.
- 모든 분석이 성공한 뒤 작업표 저장을 한 번 호출한다. 원본들은 기존 본인 전용 저장 경로에 개별 보관한다. 기본 양식 자동 저장 없음. 게이트·RLS·추출 서비스 변경 없음.

## 확인
- 실제 카카오페이 엑셀: 보험 3건, 담보 74행, 보험사/상품명/보험료 및 Hi2307 4세대 확인.
- 실제 암호화 뱅크샐러드 엑셀: 브라우저와 같은 전역 환경에서 복호화 성공, 보험 3건·담보 36행 확인. 실제 개인정보 파일·비밀번호는 저장소에 넣지 않음.
- Node 회귀 테스트 21개 통과: 형식 구분, 세대, 동의어, 조건 보존, 중복 방지, 금액 충돌, 다중 분석 실패 시 작업본 유지, 기본 양식/작업표 저장 분리.
- Chrome 임시 검증 화면: 2개 원본 → 계약 1열·담보 2행, 4세대 및 금액 차이 툴팁, 진행 안내/저장 표시 확인.
- 실제 첨부 이미지 4장의 OCR 정확도는 이번 검증에서 서비스로 재전송해 확인하지 않았다. 기존 OCR 결과를 받는 연결 단계와 합성 결과의 UI를 검증했다.
- 과거 잘못 저장된 작업표는 자동 삭제하지 않는다. 기존 결과를 다시 분석할 때 기본 양식으로 초기화 후 같은 고객의 파일만 선택한다. 다른 고객 자료를 한 묶음으로 선택하지 않는다.
