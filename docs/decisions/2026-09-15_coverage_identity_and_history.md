# 보장분석 담보 연결 사전과 담보 변천사

## 대표 확정 방향

2026-09-15 대표 지시. 이 작업은 앞으로 보장분석표 정리의 핵심 기준으로 유지한다. 단순 동의어 치환을 넘어 의료실비와 각 주요 담보의 변천사를 연결할 수 있는 구조로 확장한다.

## 표시 이름과 원본 이름 분리

- 대표가 만든 기본 양식의 행, 분류, 순서, 표시 담보명을 기준으로 삼는다. 파일을 불러올 때 원본 형식에 맞추려고 기본 양식을 덮어쓰지 않는다.
- 각 담보 행에는 변경되지 않는 식별자를 두고, 대표가 정한 표시 담보명과 파일에서 읽은 연결 담보명을 분리한다. 표시 이름을 바꿔도 연결 관계가 끊기지 않아야 한다.
- 카카오페이, 뱅크샐러드, 보험사별 원본 담보명을 해당 행에 여러 개 등록한다. 출처와 보험사를 함께 기록하며 원문은 보존한다.
- 같은 의미의 신규 회사 담보명은 기존 행에 연결한다. 보장 범위가 다른 신규 담보는 해당 대분류·중분류에 별도 행으로 추가한다.
- 파일의 자동 형식 판별과 담보의 의미 연결은 별개다. 형식별 추출을 유지하면서 검수한 연결 사전으로 대표 양식에 채운다.

## 연결과 합산은 별도 판단

- 원본 담보명이 같아도 다른 보장을 뜻할 수 있다. 보험사, 상품, 신정원 담보명, 원문 조건 등 문맥을 확인한다. 신정원 분류만으로 회사 특약의 범위를 단정하지 않는다.
- 소액암·일반암, 입원·외래·처방조제, 간병인 지원·사용, 병원 등급·병실·지급일수, 장해 지급률, 진단·치료·납입면제 등 서로 다른 범위를 무조건 합치지 않는다.
- 요약표와 상세표의 같은 보장을 중복 합산하지 않는다. 복합 담보의 공유 한도를 여러 행에 각각 더하지 않는다.
- 이름 연결은 표시 위치를 정하는 작업이며, 지급 조건 동일성이나 금액 합산 가능성을 보증하지 않는다. 불확실한 연결은 확인 대상으로 보존한다.

## 대표 검수 절차와 현재 상태

1. 현재 저장된 기본 양식을 기준으로 첨부 엑셀과 PDF의 실제 담보명을 추출한다.
2. 표시 담보명 옆에 연결 후보를 묶은 엑셀을 제공한다. 원본 출처·위치·회사명·신정원 담보명과 분리 검토 항목을 함께 남긴다.
3. 대표가 엑셀에서 연결 이름과 수정 의견을 검수해 다시 전달한다.
4. 반환된 검수본을 확인한 후 연결 사전과 편집 기능에 적용한다. 검토 초안을 자동 확정하거나 운영 기본 양식에 덮어쓰지 않는다.

이번 검토본은 기본 양식 170행, 세 파일의 원본 담보 224행(엑셀 110행, KB PDF 상세 77행·요약 37행), 별도 확인 52행으로 작성했다. 이는 이번 자료의 범위이며 전체 담보 사전의 완성 개수가 아니다. 현재는 로컬 검토용 엑셀만 전달했으며, 신규 연결 사전·편집 UI·변천사 기능은 아직 구현하지 않았다. 기존 코드의 동의어 사전은 검토 후보 생성에 참고했을 뿐 대표 승인본이 아니다.

## 주요 담보 변천사로 확장

대표가 승인한 확장 방향은 의료실비에 한정되지 않는다. 암·뇌·심장·수술·입원·간병·운전자 등 주요 담보의 시기별 변화를 같은 담보 식별 체계에 연결할 수 있도록 한다.

향후 설계 시 다음 정보를 서로 구분해 보존한다.

- 담보의 기본 개념과 대표 표시 이름
- 보험사·상품·약관 버전별 원본 명칭과 보장 조건
- 확인 가능한 판매·적용 기간 또는 기준일
- 보장 범위, 지급 한도, 지급 횟수·기간, 면책·감액·제외 조건의 변화
- 근거가 되는 약관·공식 문서의 버전, 페이지, 확인일

과거와 현재의 이름이 같다고 동일 보장으로 취급하지 않는다. 이름이 달라도 동일 개념으로 연결할 수 있으나, 시기별 조건 차이는 별도로 유지한다. 가입일만으로 세대·약관·보장 범위를 확정하지 않으며 근거가 없으면 미확인으로 둔다. 실제 변천사 데이터 조사, 화면 구성, 상세 저장 스키마는 후속 작업에서 확정한다. 이번 지시는 방향과 기준의 문서화이며 변천사 내용을 임의 작성하는 승인이 아니다.

## 권한·자료 보호

기본 양식·연결 사전의 관리와 확정은 임태성 전용 원칙을 따른다. 전체 로그인 사용자의 보장분석 이용과 본인 고객별 비공개 저장 원칙은 유지한다. 권한 정책의 별도 확대는 하지 않는다.

고객 이름·생년월일·보험료·보장금액이 담긴 원본, 비밀번호, 검토용 고객 자료는 공개 Git 저장소에 올리지 않는다. Git에는 설계 원칙과 개인정보를 제거한 구현·검증 자료만 보존한다.
