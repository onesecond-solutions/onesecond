# /insu 개인 통합 업무공간 임태성 게이트 개편

> 확정일: 2026-08-14  
> 확정자: 임태성 대표  
> 최초 적용: 임태성 계정 `98c5f4f9-10c1-4ee1-a656-5c2ca63239fd` 게이트 전용

## 제품 목표

`/insu/`를 로그인한 사용자 개인의 모든 자료를 보관하고, 고객별 상담 기록을 남기며, 해야 할 일을 캘린더로 관리하는 하나의 업무 사이트로 개편한다.

핵심 메뉴는 다음 다섯 영역으로 제한한다.

1. 홈
2. 자료
3. 고객
4. 상담
5. 캘린더

노트는 별도 고립 제품이 아니라 자료·고객·상담·일정에서 공통으로 작성하고 연결하는 기록 도구로 취급한다.

## 최상위 UX 원칙

새로운 사용법을 만들거나 실험적인 UI를 시도하지 않는다. 별도 사용 설명 없이 쓸 수 있도록 사용자가 이미 익숙한 Windows, 일반 웹 서비스, 모바일 운영체제의 표준 상호작용을 최대한 따른다.

### Windows·파일 탐색기 방식

- 폴더·파일 계층, 목록/큰 아이콘 보기, 정렬, 다중 선택, 드래그 앤 드롭을 사용한다.
- 파일명, 유형, 수정일, 크기 등 익숙한 열을 제공한다.
- 더블클릭은 열기, 우클릭은 상황 메뉴, `Ctrl+C/V`, `Delete`, `F2`, `Ctrl+A` 등 일반 단축키를 지원한다.
- 업로드한 파일은 진행 상태와 저장 위치가 명확하게 보여야 한다.
- 이동·이름 변경·삭제·복구 동작은 파일 탐색기와 같은 용어와 순서를 사용한다.

### 일반 웹 시스템 방식

- 상단 검색, 왼쪽 메뉴, 목록과 상세 패널, 표준 버튼·폼·탭·모달을 사용한다.
- 저장 중, 저장 완료, 오류, 빈 상태, 검색 결과 없음 상태를 명확히 표시한다.
- 브라우저 뒤로가기·앞으로가기와 URL 딥링크가 정상 동작해야 한다.
- 링크, 버튼, 입력창의 모양과 동작을 임의로 바꾸지 않는다.
- 동일 기능은 모든 화면에서 같은 위치·이름·동작을 사용한다.

### 모바일 시스템 방식

- 모바일은 데스크톱 화면을 축소하지 않고 한 손 조작에 맞는 단일 열과 하단 주요 내비게이션을 사용한다.
- 탭, 길게 누르기, 공유, 사진·파일 선택, 카메라 업로드 등 iOS·Android의 익숙한 흐름을 따른다.
- 터치 대상은 충분한 크기를 확보하고 호버에 의존하지 않는다.
- 모바일에서 등록·조회·수정한 데이터가 같은 로그인 계정의 PC 웹과 즉시 동기화되어야 한다.
- 별도 수동 동기화 버튼 없이 서버 저장 상태를 표시하고 자동 동기화한다.

### 반응형 기준

- 데스크톱, 태블릿, 모바일은 같은 데이터와 기능을 공유한다.
- 화면 폭에 따라 열 수와 패널 배치만 자연스럽게 바뀌며 기능을 임의로 제거하지 않는다.
- 최소 검증 폭은 데스크톱 1440px, 태블릿 768px, 모바일 390px로 한다.
- 키보드·마우스·터치 입력을 모두 지원한다.

### 금지 사항

- 레이더, 게임형 대시보드, 의미가 불분명한 시각화
- 설명을 읽어야 이해되는 아이콘과 독자적인 제스처
- 같은 기능을 화면마다 다르게 구현하는 것
- 데스크톱 전용 또는 모바일 전용으로 데이터가 분리되는 것
- 로컬 기기에만 저장되어 다른 기기에서 보이지 않는 핵심 업무 데이터
- 실제 권한과 다른 `공개처럼 보이는` 화면 표시

## 공개 범위

로그인 사용자가 자신이 만든 자료마다 다음 중 하나를 선택한다.

- `private`: 나만 보기
- `public`: 공개

화면 표시만 바꾸는 방식은 금지한다. 읽기 권한은 Supabase RLS와 저장소 정책에서 동일하게 강제해야 한다. 기존 팀·지점 공개 범위가 필요한 경우 이번 1차 파일럿 범위와 분리해 후속 결정한다.

### 2026-08-14 구현 점검 결과

기존 `scripts.scope`와 `library.scope` 필드는 존재하지만, 저장된 RLS 점검 자료에서 `scripts`는 `authenticated read scripts` 정책으로 로그인 사용자 전체 읽기가 허용되어 있다. 따라서 현재 `personal` 값을 화면에서 `나만 보기`라고 표현하거나 공개 범위 전환을 제공해서는 안 된다. 1차 게이트 화면은 기존 분류만 읽기 표시하고, 실제 `private/public` 선택은 승인된 DB RLS 변경과 교차 계정 검증 이후 활성화한다.

## 기존 임태성 게이트 자료 처리

현재 임태성 게이트에 저장된 개인 업무 자료는 새 사이트의 실제 메뉴와 카테고리로 전량 흡수 이전한다. `기존 아카이브`에만 격리하거나 사용자가 다시 등록하게 하지 않는다.

| 현재 저장 자료 | 새 사이트 흡수 위치 |
|---|---|
| 캘린더 일정 (`calendar_events`) | `캘린더`의 기존 일정 |
| 업무노트 (`scripts`) | `자료 > 업무노트` |
| 자료실 파일·링크 (`library`) | `자료 > 자료실` |
| 메모 (`library`의 메모 자료) | `자료 > 메모` |

흡수 이전은 다음을 보장한다.

- 기존 레코드 ID, 작성일, 수정일, 첨부파일, 키워드와 연결 정보를 보존한다.
- 새 메뉴에서 기존 자료와 신규 자료를 같은 방식으로 조회·검색·수정·삭제한다.
- 사용자가 기존 자료를 다시 업로드하거나 복사하지 않는다.
- 같은 자료를 새 테이블에 복제해 이중 저장하지 않는다.
- 필요하면 기존 테이블을 읽는 호환 어댑터를 먼저 적용하고, 검증 완료 후에만 물리적 스키마 통합을 수행한다.

개인 업무 자료와 별개인 현재 임태성 게이트 홈·보험 도구·지식 자료는 삭제하지 않는다.

- 새 업무공간의 기본 메뉴에서는 `기존 아카이브`로 분리한다.
- `기존 아카이브`에서 계속 조회할 수 있게 한다.
- 기존 URL·레코드 ID·첨부파일 경로를 보존한다.
- 물리적 데이터 삭제나 일괄 이동보다 먼저 통합 조회와 연결을 적용한다.
- 새 업무공간 검증 전 기존 기능·테이블을 제거하지 않는다.

보험 지식, 원수사 자료, 소식지, Q&A, 상품 라인업, 보장분석 도구는 개인 업무 데이터로 변환하지 않는다. 이들은 `기존 아카이브`와 통합 검색의 지식 출처로 유지한다.

## 기존 데이터 흡수 원칙

| 기존 원장 | 새 업무공간 역할 |
|---|---|
| `library` | `자료 > 자료실` 및 `자료 > 메모`로 전량 흡수 |
| `scripts` | `자료 > 업무노트`로 전량 흡수 |
| `calendar_events` | `캘린더` 기존 일정으로 전량 흡수 |
| `sales_customers` | 고객 원장 |
| `sales_consultations` | 고객별 상담 기록 |
| `dayfolder_items` | 종류별 자료·노트·일정 호환 입력 |
| `dayfolder_files` | 첨부파일 호환 입력 |
| `posts`, `team_notices`, `newsletters`, `knowledge_entries`, `advisor_contents` | 기존 아카이브·지식 검색 출처 |

같은 자료를 새 테이블에 복제해 이중 저장하지 않는다. 1차에는 기존 원장을 묶는 통합 조회 계층을 만들고, 물리적 통합은 데이터 실사와 검증 후 별도 수행한다.

## 사용자 흐름

### 홈

- 오늘 할 일
- 관리가 필요한 고객
- 최근 상담
- 최근 자료
- 고객 등록, 상담 기록, 자료 올리기 빠른 실행

### 자료

- 파일·폴더 업로드
- 파일·노트 통합 목록
- 미리보기, 검색, 정렬, 이름 변경, 삭제와 복구
- 고객·상담·일정 연결
- 저장 시 `나만 보기/공개` 선택

### 고객

- 고객 기본정보
- 상담 타임라인
- 연결 자료와 노트
- 다음 일정과 고객관리 일정

### 상담

- 고객 선택
- 상담일·방식·내용·후속 조치
- 다음 연락일
- 첨부파일
- 다음 연락일 저장 시 캘린더 연결

### 캘린더

- 일·주·월·일정 보기
- 직접 일정, 상담 일정, 고객관리 일정, 날짜가 지정된 자료를 통합 표시
- `전체/상담/고객관리/개인` 필터
- 캘린더가 원본 데이터를 복제하지 않고 각 원장의 날짜 정보를 조회해 표시

## 임태성 게이트 안전장치

- `_canSeePersonalWorkspace()`에서 정확한 사용자 ID를 확인한다.
- 새 뷰와 사이드바는 임태성 계정에만 노출한다.
- `?view=workspace-*` 직접 접근도 `showView`에서 차단한다.
- 임태성 이외 사용자와 비로그인 사용자의 기존 `/insu/` 화면은 변경하지 않는다.
- 검수 완료와 대표 승인 전 전체 사용자에게 개방하지 않는다.

## 구현 경계

프런트엔드는 게이트 전용 앱 셸과 통합 조회·작성 화면을 별도 JS/CSS 모듈로 구현한다. 기존 1만 줄 이상 인라인 코드에 새 기능을 계속 누적하지 않는다.

공개 범위 보안과 첨부파일 연결에는 운영 DB 변경이 필요하다. 저장소 `AGENTS.md` 규칙에 따라 Codex는 운영 DB DDL·운영 데이터 이동을 직접 실행하지 않는다. DB 마이그레이션은 승인된 CI 채널에서 별도 수행하고, 적용 전후 행 수·RLS·첨부파일 접근을 검증해야 한다.

## 완료 조건

- 임태성 계정에서만 새 업무공간 노출
- 다른 계정과 비로그인 화면 회귀 없음
- 기존 자료가 `기존 아카이브`에서 누락 없이 조회됨
- 자료 저장 시 공개 범위를 선택하고 실제 RLS가 동일하게 작동함
- 고객 → 상담 → 다음 일정 → 캘린더 흐름이 한 번에 완료됨
- 파일을 한 번만 저장하고 고객·상담·일정에 연결 가능
- 데스크톱과 모바일 검증
- 기존 데이터 삭제 0, 깨진 첨부파일 0
