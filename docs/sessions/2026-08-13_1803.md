# 세션 인계 — 데이폴더 캘린더 기본기·노트 저장 안정화

## 이번 세션 핵심 방향

- 복잡해진 원세컨드를 단순화하는 과정에서 데이폴더가 만들어졌다는 제품 배경을 재확인했다.
- 기본 캘린더에서는 고객관리 일정을 배제하고, 고객관리 화면 안에 별도의 고객관리 전용 캘린더를 둔다.
- 일반 범용 데이폴더와 설계사 버전은 동일한 공통 캘린더 엔진을 사용하며 구글 캘린더의 기본 UI·UX를 함께 흡수한다.
- 향후 `세션스타트` 명령은 현재 폴더만 보는 것이 아니라 원세컨드 전체 운영·배포·저장소·미완료 작업을 점검하는 START PROTOCOL로 실행한다.

## 오늘 완료 및 운영 배포

### 캘린더 공통 기반

- 월 보기에서 겹치는 다일 일정을 구글 캘린더처럼 연속 레인으로 배치했다.
- 기본 캘린더에서 고객관리 일정을 분리할 수 있는 공통 기반을 반영했다.
- 오래된 번들을 보고 있다가 강력 새로고침 후에만 최신 화면이 나타나던 문제를 자동 새로고침 로직으로 보완했다.
- 다른 화면을 다녀온 뒤 일정 밀도가 줄어드는 상태 복귀 문제를 수정했다.

### 주·연도·일정 보기

- 주 보기의 불필요한 별도 제목 섹션을 제거하고 구글 기준의 날짜·시간축·폰트 크기로 조정했다.
- 종일 다일 일정이 날짜별 조각이 아니라 이어지는 한 줄로 보이도록 수정했다.
- 연도 보기를 12개 월별 미니 캘린더 구조로 재설계하고 타이포를 구글 기준에 맞췄다.
- 일정 보기를 날짜 그룹·색상 점·종일 표시·다일 일정 순번이 있는 구글형 목록으로 재설계했다.
- 일정 보기의 flex 높이 계산 오류를 수정해 내부 세로 스크롤을 복구했다.

### 노트 저장 안정화

- 노트 본문을 0.9초 뒤 상태 반영하던 구조를 입력 즉시 반영하도록 변경했다.
- 노트 화면을 떠날 때 현재 편집 내용을 강제로 확정한다.
- 설계사 서버 저장 지연을 500ms에서 120ms로 줄였다.
- 전체 스냅샷 저장 요청을 직렬화하고 최신 스냅샷을 병합해 오래된 응답이 새 노트를 덮지 못하게 했다.
- 페이지 이탈 시에도 완료 가능성을 높이도록 서버 동기화 요청에 `keepalive`를 적용했다.
- 대표가 이전에 작성했으나 서버에 도달하지 않은 노트는 원본 데이터가 남아 있지 않으면 복구 불가할 수 있다. 새 버전 이후 작성분부터 재검증 필요.

## 저장소·브랜치 진실 원천

- 운영 배포 저장소: `onesecond-solutions/onesecond`, 기본 브랜치 `main`.
- 데이폴더 소스 저장소: `onesecond-solutions/dayfolder-app`.
- 주의: 데이폴더 소스의 현재 최신 운영 계보는 `master`가 아니라 `codex/advisor-supabase-visibility`를 기준으로 PR #37~#45가 누적 병합된 구조다. 집에서 작업 시작 시 이 브랜치를 먼저 fetch/pull하고 최신 여부를 확인한다.
- 데이폴더 랜딩 저장소 `onesecond-solutions/dayfolder-home`의 `main`은 이번 세션 변경 없음.
- 상위 로컬 저장소 `캘린더 앱 개발`에는 기존 사용자 변경(`src/main.tsx`, `src/styles.css`, `src/TheOneCityhall.tsx`)과 중첩 저장소가 남아 있다. 오늘 세션 작업물이 아니므로 건드리거나 커밋하지 않았다.

## 다음 세션 시작 순서

1. 원세컨드 전체 `세션스타트` 프로토콜을 실행한다.
2. `onesecond`의 `main`과 `dayfolder-app`의 `codex/advisor-supabase-visibility`를 fetch/pull한다.
3. 일반 `/dayfolder/app/`과 설계사 `/dayfolder-advisor/`에서 새 노트를 작성한 뒤 즉시 다른 화면 이동→복귀→새로고침까지 실제 계정으로 검증한다.
4. 노트가 여전히 사라지면 Supabase `sync_dayfolder_items` 요청의 상태코드·RLS·payload를 로그인 세션에서 확인하고, 저장 성공/실패 상태를 UI에 명시하는 후속 작업을 한다.
5. 캘린더는 고객관리 전용 일정과 범용 일정을 다시 섞지 않는다. 추가 구글 기능은 일반·설계사 공통 엔진에만 넣는다.

## 미해결·리스크

- 최종 노트 저장 코드는 빌드·배포·번들 확인까지 완료했으나, 대표의 실제 로그인 계정으로 작성→복귀→새로고침 종단 검증은 다음 세션 첫 확인 사항이다.
- 인앱 점검 브라우저에는 대표 로그인 세션이 없어 데이터가 0건으로 보였으며, 운영 계정 데이터 자체를 직접 조회하지 않았다.
- 데이폴더 소스 저장소의 비표준 장기 기준 브랜치 구조는 향후 `master` 정리 전까지 반드시 주의한다. 잘못 `master`에서 빌드하면 설계사 기능이 빠질 수 있다.
